# Contextory v0.5.0

Keep the application's definitions and release history alongside its code. Contextory now records what files do, which rules and features they implement, how the interface behaves, and which tests support those definitions. Project versions and changelogs cover the whole Git repository, independently of individual requests or an agent remembering to update them.

## Changes

- Add **Knowledge**: a versioned catalog of file responsibilities, rules/features with test links or explicit gaps, and interface location, element, trigger, behavior and states. Human review approves baselines and exact before/after replacements or retirements. Original definitions, reasons and immutable revisions remain available; stale approved definitions and pending changes block completion until accounted for.
- Deliver the portable **contextory-migrate** agent and resumable migration tool for projects already in development. Generated candidates stay source-backed observations with explicit uncertainty; they never become approved requirements automatically.
- Add paginated **contextory_project_export** for documentation: discover and retrieve records, definitions, immutable revisions, history, relationships, source graph, checks, jobs, usage metadata and artifacts. Documentation can distinguish current approved state from observations and historical definitions, with provenance and freshness.
- Add **Versions** and service-owned Git observation. Import locally present stable tags across branches, retain exact per-version commit membership, identify current/unreleased changes and recommend a SemVer bump from Conventional Commits. Changes made while the service was closed are reconciled on reopening.
- Prepare concrete release plans with complete version/changelog edits, HEAD, branch, configuration and remote identity. Explicitly create the dedicated version commit and annotated tag, then separately publish only that tag. Journaled retry/recovery handles interrupted writes, hooks, commits, tags and completed pushes without forcing tags or erasing unrelated work. UI, CLI and MCP share the controller; semantic records associated by recording interval are labeled separately from proven Git membership.
- Recover reused native MCP connections across delayed service/workspace restarts. Probe current readiness and tool compatibility before dispatch; never automatically replay a mutation whose response was lost. Historical MCP/hook traffic remains visible separately from observations in the current service.
- Offer a persisted **Restart Extension Host** action after changed MCP/hooks/runtime setup, with `contextory.restartAfterSetup` modes `prompt` (default), `automatic` and `never`. Add **Contextory: Check Native Connections** and **Contextory: Restart Agent Extensions**. Unchanged project reopening and skill-only updates do not create restart loops.
- Update portable skills, shared native/headless instructions, advisory hooks, user guides and the complete searchable documentation.

See [project knowledge](../PROJECT-KNOWLEDGE.md), [project versions and Git tags](../PROJECT-RELEASES.md), the [MCP reference](../MCP-TOOLS.md) and the [commit comparison](https://github.com/igormicadei/Contextory/compare/v0.4.0...v0.5.0).

## Install or upgrade

1. Use Windows, Node.js **24+**, and VS Code **1.96+** or IBM Bob with one trusted local project folder. Python 3.10+ is needed for Python source analysis.
2. Download `contextory-workspace-0.5.0.vsix` and `contextory-workspace-0.5.0.sha256` from the [GitHub release](https://github.com/igormicadei/Contextory/releases/tag/v0.5.0). Compare the package SHA-256 with the checksum file.
3. Choose **Extensions → … → Install from VSIX…**, then reload the editor. VS Code users can run `code --install-extension .\contextory-workspace-0.5.0.vsix`.
4. Reload native MCP integrations to discover the new tools. Accept Contextory's setup restart offer or run **Contextory: Restart Agent Extensions**. Resume/reopen an existing chat if its tool inventory remains old. Review native project/hook trust in the agent; restarting does not grant it.
5. Ask the agent to use **contextory-migrate** to prepare an existing application's catalog, then review the observations in **Knowledge**. Existing project records are retained; this release does not invent an approved baseline or backfill unrecorded decisions.

If an old same-version service exposes an incompatible tool contract, follow the restart diagnostic. A service still held by another project window may require closing that project's editors for 65 seconds. Preserve the same editor/CLI storage to retain authoritative project records.

## Validation and limits

The completed implementation passed **89 backend tests**, **32 UI tests**, typechecking, canonical/workspace skill checks and skill validation. Release qualification rebuilds the package, validates complete documentation and exercises the extracted VSIX in VS Code **1.145.3** and IBM Bob, VS Code API **1.126.0**. See the [validation record](../VALIDATION.md) and its package reports.

The installed Codex `codex_vscode/0.169.0-alpha.11.1` app-server passed full MCP discovery/calls, delayed service restart and resuming a persisted disposable thread from a fresh process in an isolated home with an offline provider. No model turn, credentials or user chat was used. An isolated VS Code instance also passed an actual automatic first-setup Extension Host restart, installed hook execution and unchanged reconnect without another restart. These tests do not automate the Codex chat webview or native hook trust approval.

Versions support stable SemVer and one project version; prereleases and independent monorepo package releases are not included. Observation uses locally present tags; remote tags must be fetched through the normal Git workflow. Release preparation requires a clean Git root, branch and complete history. Publishing a tag does not create a GitHub Release object, upload assets or deploy Pages; those are separate distribution steps, as performed for this extension release. Existing CI triggered by a tag still runs.

Source relationships and inferred catalog candidates are not proof of execution or exhaustive behavioral coverage. Native clients retain permissions, credentials and history. Remote/multi-root workspaces, other operating systems and large-project performance remain outside this release's qualification. Distribution uses GitHub release assets; the project remains **UNLICENSED**.
