# Contextory v0.7.0

Repair Contextory's managed hooks from the editor or a native agent, with clear guidance for native trust and safer recovery from transient Windows file locks.

## Changes

- Add **Rebuild hooks** to the Workspace Tasks footer and **Contextory: Rebuild Agent Hooks** to the Command Palette. Choose Codex, Claude Code or IBM Bob for the selected project.
- Add `contextory_hooks_rebuild`, the 36th MCP tool. It uses explicit project/provider scope and a unique operation ID, works through native and headless MCP, and retains exact retry results.
- Restore the packaged hook launcher and repair missing, stale or duplicate managed hook entries. Preserve unrelated hooks, MCP configuration, portable skills and native approval settings.
- Report repaired files separately from MCP and hook observations. An unchanged repair does not prove that native hooks ran. Review native trust and service logs instead of repeatedly rebuilding unchanged files.
- Retry transient Windows `EPERM`, `EACCES` and `EBUSY` errors during atomic descriptor/configuration replacement, with six bounded attempts and no deletion of the old destination.
- Update shared runtime instructions and portable skills with repair selection, offline editor fallback, idempotency and Codex workspace path casing guidance.

See the [commit comparison](https://github.com/igormicadei/Contextory/compare/v0.6.0...v0.7.0), [connection recovery guide](../USER-GUIDE.md#resume-an-existing-chat) and [MCP tool reference](../MCP-TOOLS.md).

## Install or upgrade

1. Use Windows, Node.js **24+**, and VS Code **1.96+** or IBM Bob with a trusted local workspace.
2. Download `contextory-workspace-0.7.0.vsix` and `contextory-workspace-0.7.0.sha256` from the [GitHub release](https://github.com/igormicadei/Contextory/releases/tag/v0.7.0). Compare the VSIX SHA-256 with its checksum.
3. Use **Extensions > Install from VSIX** and reload when prompted, or run `code --install-extension .\contextory-workspace-0.7.0.vsix`.
4. Run **Contextory: Restart Agent Extensions** or reload the native MCP configuration to discover the new tool. Resume or reopen an older chat if necessary.
5. For missing or stale hooks, choose **Rebuild hooks** and the intended provider. Review hooks in the native client when requested; Contextory does not grant native trust.

## Validation and limits

The implementation passes **105 backend tests**, **36 UI tests**, TypeScript checks and portable/workspace skill validation. Qualification includes native/headless transport, provider ownership, exact retries, project isolation, linked-runtime preservation, Windows replacement retry bounds and an isolated editor scenario that restores deleted Codex hooks without changing MCP configuration. The final extracted package is qualified in disposable VS Code and IBM Bob profiles. See the [validation record](../VALIDATION.md) and its versioned package/host reports.

A reachable Contextory service is required for MCP repair. If startup itself fails, use the editor action and inspect **Output > Contextory**. Persistent permission errors still fail after bounded retries. The installed Codex client can store different hook approvals for `C:` and `c:` paths; review `/hooks` in the affected session using its actual workspace path. Native trust approval, authenticated model conversations, other operating systems and large-workspace performance are not established by the automated checks. The project remains **UNLICENSED**.
