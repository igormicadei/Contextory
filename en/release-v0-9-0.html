Contextory / Release v0.9.0

Release v0.9.0

    Review pending knowledge in Approvals

    Approvals is a primary destination beside Work and Requests, with a pending count. Alerts and Review now open the queue directly. It fetches observed baselines and pending proposals before pagination; Knowledge remains an independent browser for definitions, history and source coverage.

    When sources changed, inspect them, enter a reason and refresh the source snapshot before approving the new revision. Refresh keeps the item pending. Inline errors explain missing/conflicting references; reasons survive navigation/failure and duplicate submissions are disabled. This does not grant agents human approval.

    Independent project explanations and Carbon

    Tools > Documentation searches English/Portuguese explanations by topic, source path or tracked record. Architecture offers Explain this area; request actions find related documentation, including links on descendant specs. Current-project source context retrieves relevant excerpts even before a new specification has explicit associations.

    The extension/CLI bundles software-documentation 1.0.1, its playbooks, the complete Carbon 1.0.0 module and local fonts/tokens/templates. No separate plugin is needed. Three Contextory tools provide reading/guidance/jobs, all upstream generator/consumer/Pages actions and audited observed associations. Text, source and meaningful record changes mark linked explanations stale.

    Reading works without Python. Generation runs only on demand with Python 3.11+ and a current lease for writes; it never blocks service startup. Existing schema-1 corpora can be read, and migration previews/backups preserve authored content before schema-2 Carbon generation. Publishing a connected project remains an explicitly authorized action.

    Install and reload integrations

    1. Download contextory-workspace-0.9.0.vsix and its .sha256 file; compare the SHA-256 before installing.
    2. Use Extensions > Install from VSIX and reload VS Code or IBM Bob. Restart native integrations when prompted so the updated tools and managed skill are discovered; native trust stays in the client.
    3. Open Approvals for pending human review, or Tools > Documentation to browse project explanations. Python 3.11+ is required only when running documentation operations.

    Qualification and scope

    Release checks cover the production UI at narrow/sidebar and short/panel sizes, backend review boundaries, native MCP/registration, disposable documentation operations and offline Carbon pages in both locales at 1440/390/320 pixels. Bundled resources are verified against 469 upstream hashes. Public publication checks compare downloaded VSIX/checksum and the complete documentation manifest.

    Node.js 24+ and trusted local Windows workspaces remain the qualified extension environment. Native hook trust, authenticated model conversations, other operating systems and remote workspaces retain their existing limits. Reference-project Contextory metadata reuse remains backlog work. Historical definitions, releases and approval state are preserved; generated explanations are not approved requirements.
