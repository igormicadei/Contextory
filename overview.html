Contextory ​

0.6.0 adds isolated projects in multi-root workspaces, project badges and coordinated requests across folders. Native MCP connections also retry delayed Contextory startup for up to five minutes. See the release notes, multi-project guide and connection recovery.

Manage requests. Give agents the full picture.

Contextory is a VS Code and IBM Bob extension that connects your requests, milestones, specifications, code, decisions, and test evidence. Keep working in the native Codex, Claude Code, or IBM Bob chat while Contextory gives the agent durable project context through MCP tools and lifecycle hooks.

Your agent keeps its own conversation, model, authentication, and editing tools. Contextory manages the project records that need to survive the next session or a switch to another agent.

The 0.6.0 package includes code intelligence and portable execution alongside automatic agent discovery, Panel layouts and native usage records introduced since 0.2.3.

Install ​

The current release is 0.6.0, a preview for Windows with trusted local project folders.

  1. Install Node.js 24 or newer. Check node --version in a terminal; restart the editor if you just installed Node.
  2. Use VS Code 1.96 or newer, or IBM Bob. The packaged extension has been tested in VS Code 1.145.3 and Bob's VS Code API 1.126.0.
  3. Download contextory-workspace-0.6.0.vsix from the release assets.
  4. In the editor's Extensions view, open the … menu, choose Install from VSIX…, and select the file. Reload the editor when prompted.
  5. Open trusted local project folders and select Contextory in the activity bar.

You can also install in VS Code from PowerShell:

powershell
code --install-extension .\contextory-workspace-0.6.0.vsix

Install your chosen native agent separately and sign in through its own interface. Python source tracing additionally needs Python 3.10+; it does not require a Python editor extension. Optional semantic search downloads its model/runtime separately. Installing the VSIX does not require npm, Rust, a database server, or a model download.

The release includes a SHA-256 checksum. Installation details, upgrades, and troubleshooting are in the user guide.

Connect an agent and start work ​

  1. Open a trusted project folder: Contextory detects installed Codex and Claude Code extensions and recognizes IBM Bob, then prepares every detected agent's MCP/hooks before its view or an agent session needs to open. For manual setup, click the agent's footer control or run Contextory: Connect Native ….

  2. Review the generated project MCP/hook configuration. Approve it through the native client's own trust flow, then reload its MCP configuration or restart its session as needed.

  3. Configure your project's check recipes in workspace settings so the agent can verify tracked specs. The user guide has examples.

  4. Continue in your native agent's chat. For example:

    Use Contextory to track this request: add retry handling to checkout. Look up earlier payment decisions, split the request into milestones and specs, inspect the affected call flow, and record the changes, decisions, and test evidence. Complete each spec after verification.

The managed contextory-workflow skill and MCP instructions describe the workflow. The agent reads context, registers its session, claims a spec, records explanations, runs checks, submits an outcome, and explicitly requests verified completion. Completing every spec rolls up the milestone and request status. Version 0.3.0 also installs contextory-codebase: it explains scoped source retrieval, relationship tracing, earlier decisions, freshness and capability fallback. Both skills share the same content across supported agents, with generic MCP export for other clients; hooks are optional.

A green agent light means configured MCP traffic has been observed. Grey means unconfigured or awaiting traffic; hover for detail. Click a gray agent button to retry setup; click an observed green button to disconnect its owned configuration. The light is not a model sign-in indicator.

Starting with 0.2.6, contextory.startupAgent defaults to auto, preparing all detected supported agents. Pause automatic setup with the footer's Auto-connect switch or contextory.autoConnect; existing connections and records stay available. Fixed providers, last-used, and none remain optional startup modes. A manual disconnect stays disabled in that workspace until reconnected. Native clients own trust and MCP reload, so first-time setup in an already-running session can still need native approval or an extension/session restart. See startup settings.

How it works ​

The extension hosts the UI and editor integration. An isolated Node.js service stores request history and handles tools. Heavier source analysis runs outside the extension host; Python source is parsed without importing or executing workspace modules. The relationship graph and optional vectors live alongside the records in SQLite, so there is no separate graph or vector database to run.

Hooks provide bounded context reminders and lifecycle metadata. They do not intercept every native action or guarantee that a model follows a workflow. The developer keeps control of native tool permissions. Contextory stores concise explanations and evidence rather than a mirror of native chat history.

See the architecture for process boundaries, data invariants, retrieval, analysis limits, and transport details.

Explore the interface ​

  • Overview: every open request with spec progress, the three latest activities, and pinned native-agent controls.
  • Requests: one card per request; expand milestones and specs inline, inspect contracts/issues/decisions/evidence/outcomes, search previous work, export reports, or explore relationships.
  • History: full paginated history with links back to the owning request, milestone, and spec.
  • Architecture: subsystem dependencies, entry points, symbol/task search, linked project decisions, source navigation, and index freshness and coverage.
  • Code map: trace from the last source cursor with a default of five call hops. The editor context-menu command Contextory: Trace Flow from Here opens a separate workbench view.

All views follow live VS Code theme changes, including custom and high-contrast themes, without resetting drafts or navigation.

The header shows the workspace name on every tab. Move Workspace Tasks to VS Code's Panel for a horizontal layout: current work and activity share columns, and the request list sits beside a spec inspector. The view adapts to its available width and height while preserving selection and drafts. The user guide explains docking and scrolling.

Storage and current scope ​

Version 0.6.0 supports up to sixteen trusted local, non-nested workspace folders. A Project selector and request/spec badges keep their records and source graphs separate. Select multiple projects when creating a request to coordinate independently verified branches; unavailable branches keep the group incomplete. Folder removal retains its storage. Native calls use explicit project scope and keep a fixed local default. See multi-project behavior. Each folder retains its existing project storage.

Native model and usage records include a specification Usage tab, request-report summaries and the agent-facing contextory_usage_get tool. Codex can supply per-request token counts; Claude supplies model metadata; Bob's documented hooks currently supply neither. Capture stays local and does not read chat transcripts. Missing counts remain unavailable. See provider coverage and task association.

Records, immutable revisions, audit events, artifacts, and service credentials live under the extension's editor-managed global storage, separated by canonical project path. Native MCP/hook configuration and workflow skills are written into the project. The user guide lists the files and explains backup and disconnect behavior.

Standalone CLI/MCP uses a separate ledger in <root>/.contextory-local/service unless an explicit storage directory or live editor descriptor is supplied. Back up that directory when using headless mode. The source graph is rebuildable; the additive schema 4 migration preserves authoritative work records.

This is a local preview. Remote WSL/SSH/container workspaces, other operating systems, large-monorepo performance, and universal language flow extraction are not qualified. Authenticated conversations in all three native agent extensions remain a separate qualification step; automated checks cover MCP workflows, hooks, configuration, and actual editor hosts. Static diagrams show possible bounded paths and expose unresolved dynamic behavior.

Version 0.2.3 uses the Contextory extension identity and tool/settings namespace. Disconnect a build installed under the previous name before replacing it. Its records remain in the former extension storage and are not imported automatically.

Governed application knowledge ​

Contextory includes a Knowledge view for file responsibilities, rules/features linked to tests, and UI layout/interaction contracts. Review concrete before/after proposals while retaining every definition revision and approval reason. Use the portable contextory-migrate agent to bootstrap an existing project, and contextory_project_export to let native agents generate documentation from all stored application datasets. See governed knowledge and documentation for usage and coverage limits.

Contextory also includes global Versions: automatic Git observation, version bumps, exact commit changelogs, reviewed release commits/tags and separately verified publication to GitHub or another Git remote. The same controller works from UI, CLI/CI and MCP without relying on agent memory. See project versions and tags.
