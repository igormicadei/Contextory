# Source documentation / Documentação de código-fonte

EN: Use this internal guide from the [coordinator workflow](../../skills/documentar-software/SKILL.md). Inventory owned modules/classes/functions/methods before editing and retain file hashes, symbol names, locations and parser provenance. Include private, nested, async, constructor and property/accessor declarations; explicitly justify exclusions for third-party/generated/vendor artifacts. Do not claim entire-app coverage from a bounded Contextory page, inferred call graph or file count.

PT-BR: Use este guia interno pelo [fluxo coordenador](../../skills/documentar-software/SKILL.md). Antes de editar, inventarie módulos/classes/funções/métodos próprios e preserve hashes, nomes, locais e proveniência do analisador. Inclua declarações privadas, aninhadas, assíncronas, construtores e propriedades/acessores; justifique exclusões de código de terceiros/gerado/vendor. Uma página limitada do Contextory, grafo inferido ou contagem de arquivos não comprova cobertura da aplicação inteira.

EN: `docs_map` uses Python AST without importing project code. Resolve parse/read errors rather than silently counting failed files as complete. For other languages, obtain a complete current symbol inventory through advertised Contextory/LSP/native parsers; inspect its cited saved source, attach current file hashes and tool/version provenance, and review missing declarations. Use the actual corpus schema for external evidence. Unsupported/unreviewed files stay explicit coverage gaps. Never fabricate a successful parser result or insert Python-style docstrings into another language.

PT-BR: `docs_map` usa AST Python sem importar o código do projeto. Resolva erros de leitura/análise em vez de contar esses arquivos como concluídos. Para outras linguagens, obtenha inventário completo e atual por Contextory/LSP/analisadores nativos disponíveis; inspecione fontes salvas citadas, associe hashes atuais e proveniência de ferramenta/versão e revise declarações faltantes. Use o schema real do corpus para evidências externas. Arquivos não suportados/não revisados continuam sendo lacunas explícitas. Não fabrique análise bem-sucedida nem insira docstrings Python em outras linguagens.

EN: Author each comment in Brazilian Portuguese and English using the language's native convention: Python docstrings, JSDoc/TSDoc, JavaDoc, XML docs, Rustdoc, Go comments, or the established equivalent. Explain purpose and contract in both languages. Document parameter meanings/units/defaults, return values, errors, side effects, ownership, state/lifecycle, invariants, concurrency and security constraints when relevant. Provide small accurate examples for non-obvious behavior; avoid translating identifiers or runtime literals. Module docs explain responsibility and entrypoints; class docs explain state and usage; callable docs describe observable behavior. Avoid generic filler that only repeats a name.

PT-BR: Redija cada comentário em português brasileiro e inglês com a convenção nativa: docstrings Python, JSDoc/TSDoc, JavaDoc, XML docs, Rustdoc, comentários Go ou equivalente existente. Explique propósito e contrato nos dois idiomas. Documente significados/unidades/padrões de parâmetros, retornos, erros, efeitos colaterais, propriedade, estado/ciclo de vida, invariantes, concorrência e segurança quando relevantes. Inclua exemplos pequenos e corretos para comportamentos não óbvios; preserve identificadores e literais de execução. Módulos explicam responsabilidade e pontos de entrada; classes explicam estado e uso; chamáveis descrevem comportamento observável. Evite texto genérico que apenas repete nomes.

EN: Place language directives correctly: preserve shebangs, encoding declarations, import ordering/future statements and compiler annotations. Documentation edits can affect introspection, doctests and generated APIs; preserve executable behavior and run the project's meaningful syntax/type/test checks. Re-map saved sources after edits, reconcile every symbol against coverage evidence, and update API pages with exact signatures and source revisions. Mark unexecuted examples and dynamic/plugin behavior as unverified until checked.

PT-BR: Posicione diretivas corretamente: preserve shebangs, codificação, ordem de imports/future e anotações do compilador. Comentários podem afetar introspecção, doctests e APIs geradas; preserve comportamento executável e execute checks significativos de sintaxe/tipos/testes. Refaça o mapa após salvar, reconcilie cada símbolo com evidências de cobertura e atualize páginas de API com assinaturas exatas e revisões das fontes. Exemplos não executados e comportamento dinâmico/de plugins continuam não verificados até sua checagem.
