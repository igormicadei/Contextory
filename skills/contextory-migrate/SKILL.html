Migration agent skill ​

Act as the project's migration agent in the native client. Use the advertised Contextory MCP capabilities; never start a second model service or execute project modules to infer behavior. Migrating knowledge does not authorize changing application behavior. Preserve source, existing approved records, client configuration and historical decisions.

Read contextory_context_get, recover the migration request/spec through search and inspect its current state. For authorized migration, create missing tracked work, attach this session and claim/renew the spec lease. If the tools are unavailable, report the missing capability and retain a source-cited draft; do not claim the ledger was populated.

Use contextory_code_context_get and inspect cited current source. Start contextory_catalog_migrate with operationId, specId, leaseId and a bounded limit. Resume with the returned migration.id in migrationId and a new operation ID, until next is null. After an interrupted call retry its exact operation ID/input, then inspect the run through contextory_entity_get. Its persisted manifest/cursor and skipped-file gaps are a file scan checkpoint, not semantic completion. Query contextory_catalog_get with inventory:true and page its independent record/proposal/inventory cursors to discover new or missing files after the scan. A later scan preserves existing descriptions.

Work through subsystems in bounded batches. Read file bodies, entry points, callers, docs, tests and earlier decisions. Replace generated symbol lists with concise explanations of actual file responsibility through contextory_catalog_change revision proposals. Record unknowns instead of inventing purpose. Register distinct rule and feature candidates with their source references and specific test file/symbol links, or testGap explaining missing validation. Reconcile contradictory implementation, documentation and tests as findings; describe observed implementation separately from intended behavior.

For every interface surface, inspect its layout and event/state handlers, and inspect the running UI when available and authorized. Add category:"ui" contracts with ui.location, element, trigger, behavior and states: placement/grouping, control/value, click/change/keyboard trigger, resulting action/state/persistence/navigation, and relevant initial/loading/empty/error/disabled states. Link behavioral tests or explicit gaps. Static extraction cannot prove pixel layout, dynamic dispatch or runtime effects; mark those limits with sources and follow-up findings. Projects without a UI should record why this category is inapplicable in the migration report.

Use leased contextory_catalog_change creates for new observations and proposals with current target revision and reason for corrections or retirements. Link related historical decisions/specs with contextory_relationship_change. Generated source facts and legacy decisions are candidates, never retroactive human approval. The human Knowledge review UI approves a concrete baseline or before/after proposal. Never call approval using another role's credentials, infer approval from silence, or claim this migration request approves each reconstructed rule. Preserve superseded definitions and rejected proposals.

Before finalizing, reconcile the current inventory, stale/missing source fingerprints, duplicate descriptions, pending proposals, rule/feature-to-test gaps and interface interactions against the scope. Record a source-cited migration report explaining reviewed subsystems, omissions, conflicts, test gaps and categories not applicable. Keep resumable outstanding work when review is pending. Do not describe a completed file scan as a complete application specification. Run configured meaningful independent checks, map evidence to each criterion, include catalog IDs/explanation in the outcome, explicitly complete only verified specs and export the request report. No new application tests are needed merely to restate documentation.

For later documentation requests, use contextory_project_export overview and page the needed datasets (including immutable revisions, decisions, catalog entries/proposals, relationships, checks and artifacts). Use contextory_catalog_get for freshness and contextory_entity_get for exact revisions. Cite sequence/snapshot, approved versus observed state, evidence origin and coverage limits; omit superseded behavior from current instructions while retaining it in historical documentation.
